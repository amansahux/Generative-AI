🚀 Module 3: Prompt Engineering


 What is Prompt Engineering?

Prompt Engineering

↓

Designing effective prompts to get better responses from an LLM.

Good Prompt =

Task
+
Context
+
Constraints
+
Output Format

Better Prompt

↓

Better Probability Distribution

↓

Better Token Prediction

↓

Better Response

Prompt Engineering improves output quality.

It does NOT increase the model's intelligence.



📚 Chapter 3.1: Zero-shot Prompting


Zero-shot Prompting

↓

Give instructions only.

No examples.

LLM uses pretrained knowledge.

Best for:

• Translation
• Summarization
• Coding
• Explanation
• Emails

Better instruction ≠ Example

A detailed prompt without examples is still Zero-shot.

📚 Chapter 3.2: One-shot Prompting

One-shot Prompting

↓

Instruction
+
1 Example

↓

LLM learns the expected pattern.

Best for:

• Fixed format
• JSON
• Classification
• Data Extraction
• Consistent output

One-shot ≠ Long prompt

One-shot = Exactly one example.

📚 Chapter 3.3: Few-shot Prompting

Few-shot Prompting

↓

Instruction
+
Multiple Examples

↓

LLM understands pattern better.

Best for:

• Classification
• Data Extraction
• JSON
• Brand Tone
• Consistent Responses

More examples

↓

Better pattern learning

↓

More tokens & higher cost


📚 Chapter 3.4: Role Prompting


Role Prompting

↓

Assign a role before giving the task.

Example:

Act as a Senior MERN Developer.

Explain JWT Authentication.

Role Prompting changes:

• Tone
• Perspective
• Style
• Depth

It does NOT add new knowledge to the model.

Role Prompting can be combined with Zero-shot, One-shot, or Few-shot.


📚 Chapter 3.5: System Prompt

A System Prompt is a high-priority instruction that defines the AI's overall behavior, rules, personality, and boundaries for the conversation.


System Prompt

↓

Defines overall behavior, rules, and boundaries.

Examples:

• Be honest.
• Be polite.
• Answer in Markdown.
• Don't reveal secrets.

System Prompt:
• Usually set by the application/backend.
• Higher priority than user prompts.

Role Prompt:
• Defines the current role.
• Can be combined with the System Prompt.

System Prompt = Company Policy

Role Prompt = Current Job

📚 Chapter 3.6: Prompt Templates

A Prompt Template is a reusable prompt with placeholders (variables) that are filled dynamically at runtime.


Prompt Template

↓

Reusable prompt with variables.

Example:

Explain {topic}
in {language}.

Runtime:

topic = React
language = Hindi

↓

Final Prompt

Explain React
in Hindi.

Benefits:

• Reusable
• Dynamic
• Consistent
• Easy to maintain

Used heavily in:

• LangChain
• OpenAI SDK
• Gemini SDK
• Production AI Apps

📚 Chapter 3.7: Output Formatting

Output Formatting means instructing the LLM to return its response in a specific format.

Kabhi kabhi model:

Extra text add kar deta hai.
Invalid JSON de deta hai.
Markdown tod deta hai.

Isi problem ko solve karne ke liye modern APIs me Structured Output aur JSON Schema jaisi features aayi hain.



Output Formatting

↓

Tell the LLM how to structure the response.

Common Formats:

• Plain Text
• Markdown
• JSON
• Table
• List

Benefits:

• Easy frontend parsing
• Consistent responses
• Better UI rendering

Can be combined with:

• Zero-shot
• One-shot
• Few-shot
• Role Prompting
• Prompt Templates

📚 Chapter 3.8: Chain of Thought (Concept)

Chain of Thought is a prompting technique that encourages the LLM to reason through a problem step by step before giving the final answer.

Chain of Thought (CoT)

↓

Guide the LLM to reason step by step.

Purpose:

• Better logical reasoning
• Better debugging
• Better planning
• Better multi-step problem solving

CoT does NOT increase model intelligence.

It encourages structured reasoning before the final answer.

Can be combined with:

• Role Prompting
• Output Formatting
• Zero-shot
• One-shot
• Few-shot
